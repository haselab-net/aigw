A guide to using AI agents on a server (Claude Code and others) from the browser on your phone or PC. Basics takes you from creating an account to doing everyday AI coding. The features installed differ a little from server to server, so ask your administrator about anything that is unclear.

aigw is a chat-style screen that opens at https://<server>/agents/. Instructions you write in the chat go to Claude Code running in your own private container on the server, and its replies come back to the chat.

1. Creating an account

If you have a Google account in a domain the administrator has allowed, you can create your own account from the aigw screen (on servers where this feature is enabled). Otherwise, ask the administrator to create one for you.

  1. Open https://<server>/agents/ in your browser and, under “Sign in with Google”, choose an account in an allowed domain.
  2. If you don’t have an account yet, a “Create account” form appears. Choose a username and submit it.
    • Allowed characters are lowercase letters, digits, - and _. It must start with a lowercase letter or _. Up to 32 characters.
    • You cannot change it yourself later.
  3. When you submit, your SSH private key is shown once and only once. Be sure to save it before closing the screen. It will never be shown again.
  4. You can now use aigw. From next time on, just sign in with Google.

Setting up SSH access too (needed to register a passkey)

If you only use aigw, you don’t need SSH. However, registering a passkey for Email and the host shell requires one SSH login, so it saves trouble to do it early. Follow whichever procedure matches your PC.

Some servers accept SSH only from inside the organization’s network. In that case, when connecting by SSH from outside, first get onto the internal network using the method your administrator provides. The aigw screen (in the browser) works from outside as is.

Mac, Linux, and MSYS2 on Windows (Git Bash works the same)

# On your PC: save the key you received and restrict its permissions
mkdir -p ~/.ssh
mv ~/Downloads/id_ed25519_<username> ~/.ssh/
chmod 600 ~/.ssh/id_ed25519_<username>

# First login. Right after logging in you are asked to set a password
ssh -i ~/.ssh/id_ed25519_<username> <username>@<server>

In MSYS2, ~ is the MSYS2 home (e.g. C:\msys64\home\<name>), which is separate from the Windows home (C:\Users\<name>). Downloaded files are in /c/Users/<Windows name>/Downloads/. A key placed in MSYS2’s ~/.ssh is not visible to PowerShell’s ssh.

Windows built-in OpenSSH (PowerShell)

Windows 10/11 comes with ssh (if it is missing, add “OpenSSH Client” under “Settings → System → Optional features”). Run the following in PowerShell. chmod is not available, so permissions are restricted with icacls.

# Move the key to C:\Users\<Windows name>\.ssh\
mkdir -Force $env:USERPROFILE\.ssh
Move-Item $env:USERPROFILE\Downloads\id_ed25519_<username> $env:USERPROFILE\.ssh\
$key = "$env:USERPROFILE\.ssh\id_ed25519_<username>"

# Make it unreadable by anyone but you (cut inheritance, grant read to yourself only)
icacls $key /inheritance:r
icacls $key /grant:r "$($env:USERNAME):(R)"

# First login. Right after logging in you are asked to set a password
ssh -i $key <username>@<server>

If you are told “UNPROTECTED PRIVATE KEY FILE” or “bad permissions”, run the two icacls lines again. In PowerShell the ~ in -i ~/.ssh/... is sometimes not expanded, which is why $env:USERPROFILE is used here.

Until you set it at this first login, your password cannot be used by anyone. From the second time on, you can log in with the same command.

Avoiding typing -i every time

Put the following in your config file and ssh aigw alone will log you in. The config file is ~/.ssh/config on Mac, Linux and MSYS2, and C:\Users\<Windows name>\.ssh\config (no extension) with the Windows built-in one. In either case, ssh reads the ~ in IdentityFile as your home.

Host aigw
    HostName <server>
    User <username>
    IdentityFile ~/.ssh/id_ed25519_<username>
If you cannot log in to aigw with an account the administrator created for you, log in by SSH and run aigw-set-email you@example.com once. You can then log in with the Google account for that email address.

3. Everyday AI coding

Normally you just choose Claude, create a session, and give instructions in the chat. Claude creates files and runs commands inside your own private container (the sandbox).

Creating a session

  1. In the creation box, choose Claude as the kind.
  2. Choose the working folder in the 📁 row. It starts at sandhome (your home inside the container).
    • Use “Open a subfolder…” to go down one level at a time, and ↑ to go up.
    • ＋ creates a new folder where you are.
  3. Normally leave the ⏱ field at “New”. To continue an earlier conversation, choose it here (see “Picking up later” below).
  4. You can normally leave “Skip permission prompts” on. Since this is inside the container, nothing outside is affected when Claude rewrites files.
  5. Give it a name (optional) and press Start; the chat screen appears.

Giving instructions and getting results

  • Write in the input box (Japanese is fine) and press Run. The return key on a phone keyboard does the same as Run (for a line break inside the input box, use Shift+Enter).
  • You can keep sending instructions while Claude is thinking.
  • Handing over a file you have: choose it with 📎 or paste it into the input box. It is saved on the server and its path goes into the input box, so follow it with something like “Look at this file and…”. Up to 100MB per file.
  • Having images or files shown to you: ask “show the resulting graph in the chat”, and Claude puts it in the designated place; an image or a download link appears in the chat. Tap a 3D model (.glb etc.) to open a viewer.

Picking up later

  • Sessions keep running, so you can continue by opening them from the list. Archiving ones you aren’t using with 🗄 tidies up the list (view archived ones with “🗄 Open the archive” below the list, and bring them back with 📤).
  • Stop: tap the green ● and confirm to stop it. Claude is sent Ctrl+C twice, the same as its usual way of quitting, so the conversation is saved (any command running in the background is stopped).
  • Resume: tap the grey ● (with a blue ring) of a stopped session and confirm, and it resumes where it left off in the same folder. The same session simply continues, and the chat so far is kept. A session that was running Claude inside a shell also resumes from where Claude left off.
  • Even if you delete a session, the conversation remains. When creating a new one, choose the same folder and pick from the date and summary in the ⏱ field to resume where it left off.

4. Sharing with others

  • Press 🧑‍🤝‍🧑 on the chat screen, choose who and what type, and press Share. It starts at Everyone, Read-only.
  • Read-only: the other person sees only the chat log. They cannot use the screen panel, send or stop. Everyone means all aigw users on this server.
  • Co-work: available only when you enter a name under “A specific user”. The other person can also send messages, type keys and stop. If you share a host shell for co-work, the other person can run commands with your permissions.
  • Root shells can only be shared read-only. Email sessions cannot be shared.
  • To stop sharing, press Remove next to the person listed in the panel.

Sessions others have shared with you go into 👥 Open shared logs below the list (like the archive, it starts closed). Open it to see one folder (📁) per owner; open a folder to see that person’s sessions. When you open a read-only session there is no input box, and “<name>’s shared log (read-only)” appears at the top.

You can also share a whole folder (Advanced).

6. How the terminal screen and the chat relate

On the server, Claude and shells run inside a real terminal. aigw shows it to you in two forms.

  • The chat is a record. New output piles up as bubbles in order, and you can read it back later or save it with 💾 inside 🧑‍🤝‍🧑.
  • The screen panel is the current screen itself. “In-place rewrites”, such as the ❯ moving in a selection menu or a progress display changing, don’t appear in the chat, so watch them in the screen panel.
  • Keys work on both. When a menu appears, open the screen panel and operate it with the key row.
  • Scroll the screen panel all the way up to go back through screens that have scrolled away. “● Back to live” at the top left returns to the current screen.
  • The 🤖 at the top right shows the subagents Claude is running in the background.

Get onto the internal network using the method your administrator provides, then SSH (Chapter 1). If you connected from outside and saved the wrong key, remove it with ssh-keygen -R <server>
