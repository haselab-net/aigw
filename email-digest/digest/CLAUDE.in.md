# 新着まとめの項目に対応するセッション

まとめページ(設定の `pageUrl`)の「AIで対応」は、作業フォルダをここ(既定 `{{data}}`)にしてこのセッションを起動する。
1通目は「新着まとめの項目 <id>「<題>」に対応したいです。」だけなので、手順はこのファイルに従う。
この利用者のこと(本人・アカウント・読む先)は `local/config.json`(`node conf.mjs get <キー>`)と `local/PROCEDURE.md`、定形ルールは `local/RULES.md`。
{{guard}}

1. `node {{bin}}/item.mjs <id>` で項目(要約・必要な対応・link・メールなら threadId)を見る。
2. 元のメッセージを読んで状況をつかみ、対応案を出す。
   - メール: `{{gmail}} thread <threadId>`(使い方は `doc --root ~/docs show gmail`)。
{{read-other}}
   - 関係する人・件の経緯は先に `doc --root ~/notes` で引く。
3. 送信・投稿・削除は必ずユーザーの確認を取ってから(`~/.claude/CLAUDE.md`)。下書きは確認なしでよい。
4. 調べて分かったことは `~/notes` に残す。
5. 片付いたら `node {{bin}}/set-status.mjs <id> 既決 "<何をしたか一行>"` で既決にし、続けて `node {{bin}}/done-sync.mjs` を実行する。
   {{done-other}}メールはアーカイブされる(gmail.py が読み取り専用のときは、表示された threadId を Gmail コネクタでアーカイブしてから `node {{bin}}/done-sync.mjs --mail-done <threadId>`)。
   既決にすると、このセッションは**その返答を終えたところで止まり、アーカイブされる**(`session-end.mjs`。Stop フックが動かす)。
   なので既決は最後の返答の中でして、その返答に何をしたかのまとめを書く。続きはまとめページの「AIで続きから」で同じ会話から再開できる。

**ユーザーがページで既決にしたとき**(2026-11-07): このセッションが生きていれば、ページは止めずに「ユーザーがまとめページでこの項目を既決にしました…」と送ってくる(項目は既決の欄に「Claude の確認待ち」で置かれ、元の片付けはまだ)。
今の作業は最後まで続け、終わったら判断する。片付いていれば 5 のとおり set-status で既決にする(元の片付けとこのセッションの停止・アーカイブが走る)。
送信の確認待ちなど、まだ対応や判断が要るなら `node {{bin}}/set-status.mjs <id> 未決 "<理由>"` で未決に戻し、理由を伝えて `状態: 要判断 — …` で番を返す(セッションはそのまま)。

**待ち**: ユーザーが「〜が来たら」「〜日になったら」続きをしたいと言ったら、既決にせず待ちを付ける。
`node {{bin}}/wait.mjs set <id> [--at 2026-11-16T09:00] [--cond "<条件>"] --task "<成立したら頼むこと>"`(条件は定期チェックの Claude が読んで判定できるように具体的に。日時は JST)。
項目はページの「待ち」の欄に移る。既決と同じく、このセッションは**その返答を終えたところで止まり、アーカイブされる**ので、待ちは最後の返答の中で付け、その返答に何を待つかのまとめを書く。日時はサーバーが1分ごとに、条件は定期チェックが判定し、成立すると未決に戻ってスマホに通知が届く。
「AIで続きから」を押すと「待っていた条件が成立しました(…)。頼まれていたこと: …」が届くので、そのとおり進める。外すときは `wait.mjs clear <id>`。

**状態の申告**(aigw のやること一覧と通知、2026-11-07): aigw が求める最後の行「状態: …」は、このセッションでは次のように読み替える。
- 済みか待ちかは「何も起きなかったら、誰かが動く必要があるか」で分ける(2026-11-09 ユーザーと決めた)。返信・依頼をしただけで済みにしない。
  - 返事が来なくてもよい(来れば新着まとめが新しい項目として拾う): set-status で既決にし、`状態: 済み — …`。例: お礼・了承の返信、カレンダー登録。
  - 返事や反映が無いままだと困る: 上の wait.mjs で待ちを付ける。自然な期限が無ければ1週間後を `--at` にする(「無ければ催促」などを `--task` に)。例: 確認の依頼、資料の送付依頼。
    申告は `状態: 寝かせ 11/16 9:00 — 〈条件〉(新着まとめが通知)` とする(期限と条件は新着まとめが持ち、成立したら新着まとめが通知する)。
- ほかの aigw セッション(root など)に talkto で仕事を頼んだら、その仕事は相手が持つ(2026-11-09 aigw の決まり「ボールは次に動くセッションだけが持つ」)。
  こちらは待ちを付けずに既決にし、`状態: 済み — 〈相手〉へ引き継ぎ` とする。結果を受けてこちらで続ける仕事があれば、そのとき相手が知らせてくる(このセッションはアーカイブ済みなので、届かなければ新着まとめの「AIで続きから」で再開する)。
- `状態: 済み — …` は、set-status で既決にして片付けた返答だけに付ける(既決の返答で止まってアーカイブされ、aigw は通知も一覧も出さない)。
- `状態: 要判断 — …` は、既決にも待ちにもせず番を返すとき(送信・投稿・削除の確認、本人の判断や情報が要るとき)。
- 申告の文は件名程度・40字まで。本文の中身・金額・個人情報は書かない(スマホの通知に出る)。

続きから再開したときに「この項目は前回から更新されています」と届いたら、新しい返信などが来ている。
`item.mjs` と元のメッセージを読み直し、前回からの変化を先に伝える。

**定形ルール**: ユーザーが「今後〜が来たら…して」と頼んだら、今回の分を処理したうえで `{{local}}/RULES.md` にルールを足す(書き方はそのファイルの冒頭。無ければ `RULES.example.md` を写す)。定期チェックが以後自動で処理する。

定期チェック(`run-check.sh`)は `~` で動くので、このファイルは読まない。
